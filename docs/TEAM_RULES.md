# 共通ルール

## 作業の進め方

1. 作業開始前に、触る予定のフォルダと共有ファイルをチームへ伝える。
2. 各自は自分の担当フォルダを中心に作業する。`shared/` の変更は先に相談する。
3. 小さな単位でコミットし、コミットメッセージには担当と内容を日本語で書く。
4. 他人の変更を上書きしない。コンフリクト時は、意図を確認してから解消する。

## 競合を避けるルール

- 起動処理、画面遷移、共通CSSは須賀が最終統合する。実体は最終的に `src/main.js` と `src/styles/` に置く。
- ステージJSONの形式は白鳥が管理し、変更時は `shared/STAGE_FORMAT.md` を更新する。
- 認証と保存は白石が提供する共通API経由で使う。ゲーム画面からSupabaseを直接呼ばない。
- マスの見た目とゲームCanvas描画は末田が管理する。

## ライブラリの追加

- 追加済み：Vite、`@supabase/supabase-js`、`zod`。
- 新しいライブラリを入れる前に、用途・導入理由・代替案をチームへ共有する。
- 短期間のため、UIフレームワークやゲームエンジンは途中から追加しない。Canvas 2Dと素のJavaScriptを維持する。

## 機密情報

- Supabase URL・匿名キーなどの実値は `.env.local` に置き、Gitへコミットしない。
- 共有するのは `.env.example` のキー名だけにする。

## 完成前チェック

- ログインなしのゲストプレイができる。
- ログイン済みならセーブ対象のユーザーIDを取得できる。
- ステージJSONを編集側・プレイ側の両方で読める。
- ホームからゲーム開始まで遷移できる。
